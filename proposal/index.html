학습설계 툴과의 분업 같은 목적, 다른 경로

  • 학습설계 툴(설계) - 기이수 인정부터 학기 배치까지 담당자가 쌓아 올리는 화면. 보유학점·자격증 케이스용
  • 원클릭 제안(제안) - 규칙이 만든 결과를 담당자가 승인만 하는 화면. 보유학점 없는 일반 케이스용
  • 대상은 학습설계를 신청하지 않은 학습자 - 학습설계 신청은 학습자가 직접 하는 일이고, 신청이 들어온 건은 학습설계 툴에서 맞춤 설계로 간다. 이 화면은 신청하지 않는 사람에게 먼저 제안을 보내는 쪽이다
  • 그래서 목록에 신청구분·실명인증은 두지 않는다 - 아직 신청 자체가 없으므로 채워질 값이 아님
  • 진입점은 제안 목록 관리 - 본인 담당 학습자를 이름(회원ID)·연락처·최종학력·목표과정과 함께 한 줄로 보고, 제안하기 열에서 바로 제안안 팝업을 띄움. 미제안만 체크로 아직 안 보낸 건만 추림
  • 목록의 상태 · 열람 여부 · 결제 여부로 발송 이후까지 같은 화면에서 추적 - 미열람 건이 팔로업 콜 대상

패키지가 출발점 LMS 패키지관리 데이터를 그대로 읽음

  • LMS 패키지 레코드는 과정 × 개강차수 단위 - 사회복지사만 451건, 전체 1,529건
  • 구성이 같고 차수만 다른 레코드가 반복되는 구조 - 번호 컬럼(노출 순서)이 상품 슬롯 역할
  • 원클릭 = 분류로 좁힘 → 슬롯별로 모집중 중 가장 이른 개강 1건씩 집음 → 학력 규칙으로 2~3개만 남김
  • 담당자가 보는 건 1,529건이 아니라 항상 카드 2~3장
  • 제안안 팝업에는 학습자 신원(이름·최종학력·목표과정·주소지)과 카드만 둔다 - 선별 방식과 추천 근거는 매번 같은 설명이라 이 기획설명에 모아 두고 화면에서는 뺐다

수강료 미표시 2026.08.20 수시회의 결정

  • 제안 화면은 과목 목록만 표시 - 금액은 수강신청·결제 단계에서 처음 노출
  • 근거 - 앞단 수강료 노출이 혼란을 유발하고, 쿠폰이 결제 화면 하단에 있어 학생이 놓치는 사례 다수
  • LMS 상세의 과목단가·총결제금액 구조는 그대로 두고 결제로 넘길 때만 사용

만료·마감은 기존 필드로 처리 신규 개발 아님

  • LMS에 진행상태(모집중·마감) · 신청노출여부(노출·비노출) · 모집기간이 이미 있음
  • 제안 유효기간 = 선택된 개강반의 모집 마감일 자동 산출 - 담당자가 날짜를 입력하지 않음
  • 마감 패키지는 학습자 화면에서 비활성 + 문의 유도 - 별도 삭제 작업 불필요
